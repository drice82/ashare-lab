# 数据同步

环境变量：TUSHARE_TOKEN、TUSHARE_HTTP_URL（默认 https://api.tushare.pro）、DATA_DIR、DATABASE_PATH、TZ=Asia/Shanghai。SDK 1.4.29 已核实协议，DataApi 没有公开 URL 参数，因此使用 httpx 直接实现相同 Pro 协议，业务层只依赖 DataProvider。

初始化默认最近三年，日线向前补 120 个日历日；分红按股票读取全部可用事件（接口从 2000 年起），日历覆盖预热期。新任务顺序：股票 L/D/P → 日历 → 各交易日日线/因子/基本指标/可选数据 → 未退市证券分红。增量回查最近 10 个日历日，重新查询分红，捕获补录和修订。基础退市记录继续刷新以判断排除范围，退市证券不再逐只补数；新策略任务的按交易日行情响应也按本轮基础证券版本的list_status=D排除退市证券。旧策略任务保留历史股票池。历史名称由独立月度任务按未退市证券逐只获取，普通初始化和增量均不触发名称查询。

默认 40 请求/分钟，HTTP 超时 30 秒，临时失败/限流指数退避，最多 4 次；权限/认证错误立即分类，不重复请求。每一请求有固定检查点。成功分片独立发布，后续失败保留已有数据并显示真实失败。

远端连接协议错误（`httpx.RemoteProtocolError`，例如服务端断开连接）与超时、网络错误共用重试及限速机制，退避1/2/4秒；四次请求均失败时返回脱敏的`temporary_error`，不记录原始异常、请求或Token。用户可从原任务检查点恢复，已发布数据与旧版本保留。

返回达到已知上限不能视为完整：股票按交易所拆分，日线类按股票拆分，新名称任务始终逐股票查询，不先获取全市场；5000为截断保护阈值，不是股票数限制，文档没有明确额度时不随意放大。旧同步任务沿用原全量及逐股回退策略。分红已逐股票查询；单股票仍达到上限时明确失败，V0.1 未实现继续拆分，不发布截断结果。HTTP 状态和 Pro code 都检查，未知错误不归为无数据。

发布流程：标准化及校验 → 分区旧数据合并去重 → 临时 Parquet → 原子 rename → SQLite 事务更新版本清单与检查点。旧清单和文件不删除，已有筛选可重现。异常留下的未引用文件不影响查询。

按交易日查询的全市场行情响应先检查原始行数上限，再排除北交所、B股等范围外证券，然后标准化并严格校验沪深A股。历史响应中 `T` 加5或6位数字、后缀为 `.SH` 或 `.SZ` 的特殊代码（如 `T00018.SH`、`T600018.SH`）也按范围外证券过滤，不将其改写为普通A股代码；基础证券信息中的特殊记录继续保留。范围外行数记入日志；其他格式错误或缺失的代码仍进入校验并报错，不静默丢弃。逐股票查询继续校验返回股票与请求一致。沪深A股价格缺失或非正数仍拒绝整批发布，错误列明股票、交易日及字段；不补填昨收价，不读取未来行情。市场范围过滤不依赖当前名称或退市状态。另对新同步策略任务，在标准化前按本轮stock_basic数据版本明确排除list_status=D的代码并记录排除数量；未知状态、缺失或非法代码仍严格校验。原始行情确有响应但全部属于已退市证券时允许发布零行覆盖（不代表任一存续股票有行情）；原始范围内行情为空仍报错。旧任务的股票池语义及已发布版本保持可读。OHLC错误列出股票、日期及四个价格，不改写错误报价。

完整性包括查询成功范围、是否截断、预期/实际记录、股票级缺失。无日线可能为停牌、未上市、退市或未知；不能一律当停牌。可选 stk_limit/suspend_d 权限不足记录降级；缺少关键行情、复权、分红或历史名称时相关规则返回未知。

交易日历要求请求范围内每个自然日都有记录，开市标记只能是0或1，避免压缩缺失交易日后错误计算窗口。指定日期/股票的响应必须与请求一致。分红及名称覆盖记录含 as_of_date；覆盖截至日早于筛选日时相关因子返回未知。覆盖记录逐分片追加，版本只保存水位，读取旧版本时按水位重建覆盖，避免全市场逐股票同步复制不断增长的完整覆盖表。

接口核对（2026-10-09）：stock_basic 2000 起/6000 行/50 次分钟；trade_cal 2000；daily 6000 行，未复权、停牌无记录；adj_factor 2000 起；daily_basic 2000 起/6000；dividend 2000 起/2000；stk_limit 2000/5800；suspend_d 2000/5000。daily 文档与权限总表频次不同，采取较低默认值。namechange 文档未明确额度，运行时探测。

官方来源：https://tushare.pro/document/2?doc_id=25、26、27、28、32、103、183、214、100、290；SDK：https://github.com/waditu/tushare/blob/master/tushare/pro/client.py。文档不等于账号权限，必须以实际响应验证。最终阶段凭据已可用，九个接口完成单股票真实响应和标准化验证，suspend_d为空响应；详细范围见verification.md。全市场三年覆盖与长期调用额度仍待验。
# 请求并发与限速

`SYNC_CONCURRENCY` 默认4（1–16），只并发HTTP读取：历史名称、分红按股票有界预取；同一交易日的五个行情接口并发读取。每批最多保留并发数个响应，由单一调用线程按顺序校验、发布版本和检查点，避免并发发布覆盖清单。取消/异常停止新预取、取消排队请求并等待正在运行的请求结束；未发布响应在恢复时重新请求。权限不足按数据集降级，截断仍拆分，完整性校验不变。

所有线程和重试共享一个带锁的请求起始间隔限速器，`REQUESTS_PER_MINUTE` 是整个Worker的总上限；并发不能绕过账号配额。默认仍40，当前2000积分账号部署override设为200、并发4。限流响应按原有指数退避重试，不保证一定达到配置吞吐。只有一个Worker持有仓库写锁。


月度任务首次刷新基础信息后，将股票代码清单与覆盖截至日期持久化进任务snapshot；恢复沿用原清单和日期。每月首个周六02:00（Asia/Shanghai）到期，Worker每分钟检查；settings中的namechange:YYYY-MM记录与任务入队同事务，重启不会重复提交。错过多月仅补交最近到期月份，失败、取消和部分完成不自动重建任务。fixture或无Token不自动入队。无历史名称的新仓库等待月度任务或用户手动提交，不返回虚假完整状态。

## 分红与名称增量（当前策略）

调度时间为北京时间：分红每日01:00、名称每日02:00；每月首个周六分红03:00、名称05:00全量校正。凌晨扫描截止到前一天，行情每日16:00不变。已有完整历史复用，不在首次升级补交已覆盖的全量校正。

分红按公告日、实施公告日、登记日、除息日逐日查全市场变化，汇总代码后逐股完整替换；最近365天未实施或派息缺失/未到期记录也加入目标。名称按公告日期区间发现，补齐新股及基础名称差异。参考供应商接口：<https://tushare.pro/document/2?doc_id=103>、<https://tushare.pro/document/2?doc_id=100>。接口没有最后修改时间，30天回查不保证发现所有修订，每月全量承担窗口外校正。

history:observation只在发现完整且所有所需股票已刷新后提交；日期查询结果保存在任务snapshot，股票历史发布沿用持久checkpoint。部分完成、取消、权限不足、未知截断或已有历史返回空不推进观察水位。最终版本覆盖和成功任务状态同事务发布，恢复和旧版本读取仍有效。完整基线与观察截至日分开保存，筛选与定投使用同一判定。

## 统计摘要补齐与兼容

`ashare statistics`对当前各数据集的固定版本补齐并预热统计，支持重复运行及中断后继续。文件行数和日期范围优先读取Parquet元数据，缺失统计时只读取相关日期列；精确股票数读取代码列去重后按版本求并集。统计不读取供应商，不改动行情或历史版本；空文件/空清单返回真实零行和空日期。

统计表通过0003加法迁移建立，旧版本仍按旧清单读取。新文件摘要与数据发布事务一起提交，未完成的版本摘要不会可见。只变更覆盖的版本也会获得独立版本摘要，但沿用未变文件的统计。历史文件补齐每256文件提交，故中断最多重读正在处理的一批。可在升级API前预热当前版本，避免首次请求承担补齐耗时。回滚旧镜像时保留派生表，不删除市场文件或执行破坏性降级迁移。

回滚兼容性：直接使用不认识0003的原镜像会在Alembic初始化时报未知版本。已保留`ashare-lab-backend:pre-load-fix-compatible`：原业务代码，仅补入0003迁移声明；隔离的0003真实目录初始化通过，九个数据集头保持可读。回滚使用该兼容镜像及原Web镜像`ashare-lab-web:pre-load-fix`，保留统计表和Alembic水位，不执行降级/删表。旧查询逻辑的性能问题仍存在，回滚仅用于故障恢复，重型研究应暂停至优化版本恢复。

## 任务通道

常驻Worker中，数据更新固定一个独立执行名额，研究任务最多两个名额；更新任务之间仍按提交时间排队。研究使用原固定版本读取不可变文件，不随更新切换数据头。历史观察水位成功发布前先停心跳，同一事务保存完成状态及最终日志，之后Worker不再访问该任务记录；检查点、中断恢复和重复同步口径保持不变。
