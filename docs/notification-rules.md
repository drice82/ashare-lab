# 日线信号通知 V1

信号通知使用邮箱验证码登录，无需密码或网站共享访问密钥；首次验证成功自动创建账号。登录邮箱同时作为唯一邮件收件地址。六位验证码有效10分钟、最多五次尝试；重发使旧码失效，验证成功即消费。登录及更换邮箱按用途隔离，更换验证码同时绑定当前账号。邮箱去首尾空白并统一大小写，不合并点号或+别名。账号邮箱使用Fernet密文，验证码使用HMAC摘要，会话只存SHA-256摘要；均不记录原始凭据。

会话Cookie为HttpOnly、SameSite=Lax，默认180天，生产启用Secure。同一邮箱支持多设备同时登录；退出只撤销当前设备会话。普通登录不改变渠道、订阅、渠道修订、待发消息或退订状态。首次登录的新账号自动创建已验证邮件渠道；停用邮件通知不删除账号邮箱，重新登录不会自动启用邮件渠道或恢复已退订订阅。

登录后可验证新邮箱以同时更换登录及收件邮箱。请求验证码时保持原配置；验证成功后原子修改账号邮箱及邮件渠道，保留订阅和Webhook，取消旧邮箱待发消息、更新邮件修订使旧退订链接失效、撤销旧会话并建立当前浏览器新会话。已停用邮件渠道仍保持停用；邮件订阅沿用下一交易日起生效规则。新邮箱已属于其他账号或待接续旧身份时拒绝更换，不自动合并。旧邮箱再次验证只能得到独立的新账号，不能访问迁出的订阅。

Alembic0005保留既有owner_id和业务记录，旧匿名会话与恢复码统一失效且不再提供创建/恢复接口。已验证的旧邮箱首次登录时接续原身份的订阅及历史记录（Bark在后续0006按下述规则停用），不改变既有邮件修订。规范化后邮箱对应多个旧身份时拒绝自动关联，由管理员处理；无已验证邮箱的旧身份保留数据。旧鉴权字段仅保留结构兼容，使用不可匹配SHA-256凭据的失效占位值；新鉴权只使用账号、会话和验证码表。

每个账号最多一个 Webhook 地址及一个已验证邮箱，每条订阅绑定一只存续沪深A股、一种技术策略、一组适用参数、非空信号方向和非空渠道列表，默认买卖双向和已验证渠道。默认上限20条，相同完整配置返回已有订阅。创建、修改策略/方向/股票、增加渠道、恢复及替换接收目标，在操作日之后的下一交易日起生效。删除保留历史检查与发送记录。取消渠道仅取消该渠道待发送消息；暂停、修改策略、删除取消旧配置的待发送消息。

Webhook URL为用户接收配置，可能包含凭据；沿用原Device Key业务配置的Fernet加密保存方式，不回显完整地址、不记录日志。管理员供应商Token、SMTP密码和Fernet密钥仍只通过环境配置提供。Webhook仅接受公网HTTPS URL（最长2048字符），禁止userinfo、fragment、非公网地址；绑定及每次发送重新验证全部DNS地址，并固定连接至验证过的公网IP，同时保持原域名的TLS证书校验与Host。禁止重定向及环境代理。固定POST JSON `{title,body,group:"ashare-lab"}`，15秒超时，HTTP2xx表示服务端接受；Bark官方api.day.app另外检查code=200。自建Bark按通用HTTP接受口径。绑定发送测试通知，正文为“这是一条测试通知”，成功才验证渠道。邮件统一SMTP；邮箱加密保存，仅显示脱敏地址；登录验证码同时确认邮箱归属，更换邮箱验证成功后取消旧邮箱待发消息。

0006迁移停用旧Bark渠道、取消其pending/sending消息，从非删除订阅移除bark。仍有邮件的订阅继续，邮件修订与队列保留；无剩余渠道的暂停并提示重新配置。历史Bark记录不改类型，前端不再提供“Bark（旧渠道）”查询选项；旧接口查询参数保留兼容。旧Bark接口和发送器移除，重新绑定Webhook不会自动修改或恢复旧订阅。Bark对接填`https://api.day.app/<Device Key>`（自建服务填对应公网HTTPS地址），然后绑定测试，参见[官方教程](https://github.com/Finb/Bark/blob/master/docs/tutorial.md)。

页面分为订阅管理、发送记录、账号与渠道。创建选择股票后保留名称和代码；订阅列表名称来自当前固定基础快照，仅作管理展示，历史记录名称仍来自信号当时的outcome。参数显示中文标签及交易日/倍数单位，启用和暂停同时用文字、图标及颜色区分。成功提示4秒后消失且可手动关闭，错误及退订确认不自动消失。

## 固定日期与信号口径

通知固定交易日及 stock_basic、trade_cal、daily、adj_factor、suspend_d 版本和策略版本。窗口及所有日期行情读取上界不超过信号日，既有版本不跟随后续发布改变。排除基础版本中已退市证券，不以当前名称判断历史ST；展示名称来自所固定的基础版本，通知不提供历史ST过滤。

五种策略共用 `signals.py`；回测保留原交易引擎和版本语义。信号只计算指标，不运行资金、成交、持仓和分红模拟。窗口与“信号日作为回测开始日”相同，取以下数量的此前交易日加信号日，按信号日复权基准计算（双均线前一日窗口沿用旧引擎前一日复权锚点）。

|策略|此前交易日数|触发规则|
|---|---|---|
|双均线|long_window|短均线上穿长均线买入、下穿卖出，保留原浮点容差|
|MACD|5 × slow_window + signal_window|DIF上穿DEA买入、下穿卖出；EMA以窗口首个完整周期SMA初始化|
|RSI|5 × period + 1|上穿下阈值买入、下穿上阈值卖出；首周期涨跌平均值初始化，再用Wilder平滑|
|布林带|period|下轨外回到轨内买入，上穿中轨卖出；总体标准差，同日双信号卖出优先|
|唐奇安|max(entry_window, exit_window)|突破此前最高价买入、跌破此前最低价卖出；窗口不含当天|

缺少窗口日历、行情、复权因子或完整覆盖返回数据不足，等待最新版本；停牌、零成交量不推送。已完成的检查保存方向、依据、数值指标、窗口和版本。不同交易日重复产生同方向信号继续提醒，不依赖模拟账户是否持仓。

Worker启动后以及每分钟，北京时间16:00后仅检查最近已收盘交易日。日历未覆盖应有日期时等待，不从旧日历推断最近日期；行情未就绪时不退回更早交易日。恢复后不补发过往交易日。算法版本不兼容暂停检查并提示更新订阅。

## 投递及退订

信号检查与每渠道消息同一SQLite事务落库。检查以订阅/修订/日期唯一；发送以订阅/日期/方向/渠道唯一。共享相同股票、参数、日期和版本的持久计算任务，复用研究执行通道。Webhook和邮件各一个发送线程，网络请求不持有数据库写事务。发送前复查状态、配置修订及渠道修订；启动恢复 sending 为 pending。临时错误初次发送加最多四次重试，间隔1、5、15、60分钟，Webhook429尊重Retry-After。最新交易日收盘后更早日期的未发送消息过期。

Webhook永久凭据错误或SMTP永久收件人拒绝停用对应渠道；SMTP认证、发件配置或TLS错误记录服务不可用，不降级明文。修改SMTP配置并重启API/Worker后新的配置指纹解除旧配置故障状态。验证码及测试由用户主动请求，失败页面显示简洁原因，用户可重试。正式信号记录中，Webhook接受（官方Bark校验业务响应）、SMTP接受后均称“服务端已接受”；手动测试的界面反馈为“测试通知已发送”，并不改变accepted的技术含义。不能保证手机收到、进入收件箱、用户阅读；接受之后超时重试可能重复，V1不承诺端到端恰好一次送达。每封信号邮件包含文本及HTML、单一收件地址、固定发件人和重试不变的Message-ID。

邮件中的专用退订链接凭据位于URL fragment，前端读取后清除fragment，GET不产生退订；确认按钮用POST请求体提交。凭据只授权当前订阅邮件退订，不授权查询管理、不影响Webhook；邮箱修订改变后旧凭据失效。仅邮件的订阅退订后暂停且渠道为空，恢复须通过修改重新选择已验证渠道。

登录及更换邮箱验证合计每IP每小时10次，写请求每IP每分钟60次；发送请求另限每IP每分钟10次、每天100次。验证码/绑定对同一目标每分钟一次、每天十次。渠道测试、Webhook重新启用测试与订阅测试共享账号滚动额度：一小时内前五次可连续发送，之后两次至少间隔60秒，每小时最多20次；一次订阅多渠道发送计一次。额度持久化并原子预留，实际发送失败计次，前置校验失败和限流拒绝不计次，429提示等待秒数；原IP保护仍适用。计数持久化，默认忽略所有代理头，仅明确可信的代理IP/CIDR可传入X-Real-IP。所有通知写请求检查Origin，所有私有查询和写入检查邮箱账号会话和记录归属。未知通知路由不享有共享密钥豁免。

fixture界面有醒目标识，任何固定的依赖版本或当前版本为fixture时不自动计算/发送；显式测试始终带测试标识。V1暂不含盘中、自定义策略、筛选规则订阅、邮件摘要和阅读追踪。


## 手动订阅测试与渠道启停

账号与渠道及创建订阅均先展示邮件，再展示Webhook。两个渠道均提供启用/停用按钮和不同颜色的状态徽标。停用保留加密配置，撤销验证并递增渠道修订、取消该渠道正式待发送消息；邮件重新启用使用已验证登录邮箱，Webhook重新启用需真实测试成功后验证。启用不会恢复旧队列或已退订订阅。

每条订阅可测试，暂停订阅也允许手动测试。单方向直接发送，双方向由用户选择买入或卖出；仅发送至订阅选中的已验证、已启用渠道，部分不可用渠道在当次结果显示跳过原因，全不可用返回409且不计额度。示例沿用正式信号模板，包含股票、策略和参数，标题标注“测试”，信号日期、依据、指标明确标为示例，不读取真实行情或伪造信号数据版本。示例邮件不附带真实订阅的退订链接。

独立测试表保存各实际发送渠道的结果，与正式信号的检查、去重、队列和最近检查日期隔离。测试在网络调用前持久化unknown状态，成功后accepted，已知发送错误failed，无法确定结果或进程中断维持unknown；不自动重试。发送记录合并正式记录及订阅测试，明确标注测试和测试时间，支持统一渠道筛选、总数和分页。fixture模式仍醒目标注，手动示例允许真实测试发送。
